# annotate-spatial-transcriptomics v2.5 执行链稳定化修复计划

> 日期：2026-07-30
> 状态：已完成代码实现、只读故障重放和发布前验证；未投递样本计算任务。本计划不记录 GitHub 发布状态。
> 当前已实现：统一 runtime dependency registry、通用 membership transform chain、严格串行逐细胞类型专项队列、固定 GSE233801 split-wall Atlas、标准 SCT+BANKSY bootstrap、受控暂停状态物化、final release transform 绑定、可恢复最终 RDS/图表/HTML 交付；bootstrap 会把 non-SCT raw-count assay 及 input audit 冻结进 contract，绝对值 dotplot 与并行 `pigz` 原子 RDS writer 已通过真实微型 Seurat 验证。
> 证据范围：C05487C6 同事完整运行日志、D05521C3 事故登记及 P85/P86/P87 运行产物、当前 GitHub `v2.5.0` 与已安装 Skill 的只读差异。

## 一、结论

v2.5 的生物学主架构已经基本明确，但正式执行链仍不够闭合。当前最大问题不是某个 marker 或阈值，而是：

1. 正常新项目也会在输入、contract、BANKSY 网格、Atlas、逐大类复核和最终交付阶段缺少标准入口。
2. Agent 为继续任务而临时编写项目脚本、生成 stage authority、迁移 contract，甚至直接修改已安装 Skill。
3. 多次 ROI 修复、精确撤销标签和 source-unit 同步形成连续 membership 变换后，completeness 只能识别简单单步路径。
4. 预检主要验证文件、hash、schema 和依赖是否存在，没有真正执行“标准流程会走到的组合路径”。
5. `REVIEW_REQUIRED`、`ITERATION_REQUIRED` 和真正的软件失败在调度器层面经常都表现为任务 `EXIT`，造成反复停止、误判和重复投递。
6. 最终报告和 RDS 写回尚未成为控制器内的完整标准交付阶段，导致项目再次自编脚本。

因此，下一轮修复不应增加新的生物学门，也不应继续针对某个样本添加特殊分支。应在保持现有注释算法、taxonomy 和逐大类复核原则不变的前提下，把执行链收敛为：

`标准输入冻结 -> 唯一 contract -> 标准阶段控制器 -> 通用 membership transform ledger -> 串行逐细胞类型专项复核 -> 标准 final release`

任何正式项目都不应再依赖项目本地 scorer、decision builder、authority builder、contract adapter 或 final writer。

## 二、审计事实

### 2.1 C05487C6 新项目暴露的问题

1. **输入冻结没有标准入口**
   - 先后编写 `audit_blind_input.R`、`audit_blind_input_v2.R`。
   - 因 `data.table::fread()` 读取 gzip 时缺少可选 `R.utils`，输入任务失败后重投。
   - 上游 304,919 个 pre-QC observation 与 RDS 内 296,188 个 analysis observation 的边界直到第二次修订才固定。

2. **contract 生成器与控制器依赖清单不一致**
   - 控制器要求 `audit_local_split_workload.py`，但 v2.5 contract builder 没有绑定。
   - 同事运行中直接修改已安装的 `build_annotation_contract_v2.py` 后重建 contract。

3. **BANKSY 输入 schema 没有统一适配器**
   - 上游分区完整，但缺少控制器专用的 `boundary_id`、`resolution_role` 等字段。
   - 项目本地对表格做纯格式修订后才继续。
   - local-split workload audit 又遇到 `stage` 与 `phase` 的别名不一致。

4. **Atlas 不是标准可复用资产**
   - 运行中临时编写 GSE233801 reference 构建、标签物化、索引、query export、calibration 和 discrepancy decision 脚本。
   - 旧固定索引把 GSE233801 的 c8 Smooth muscle、c12 Pericyte 与 c2 Stroma 合并，并把多个 endothelial cluster 合并为旧血管标签；能力不足来自索引 taxonomy，而不是 GSE233801 原始参考缺少这些成分。
   - 这种 Atlas 应有明确的 lineage capability ceiling，而不是每个项目重新构建和解释。

5. **初始分区和局部拆分负载值得复核**
   - BANKSY 0.8 形成 18 个 cohort，运行记录将它们全部作为 mixed 处理。
   - 一次局部拆分后仍留下约 51,000 个 unresolved，再由 Atlas 救回 22,796 个。
   - 这不一定说明分辨率错误，但说明 whole-tissue selection、mixed trigger 和 workload audit 需要一体化测试，不能只在正式样本上发现负载异常。

6. **ROI 修复需要运行中修改共享 Skill**
   - 运行中修改 `apply_sheep_ovary_follicle_roi_repair.py`、`run_lineage_controller.py` 和 `audit_post_merge_completeness.py`。
   - 同时出现 `build_r6_contract_adapter.py` 及 r5–r9 多份 contract/profile 复制。
   - 这使同一个项目不再由一个不可变版本和 contract 解释。

7. **逐大类复核仍依赖项目自编程序**
   - 项目本地创建 round-1 decision builder、stage-authority builder、round-2 runner、round-3 verifier。
   - 还直接修改了已安装的 decision validator。
   - 即使最终四项证据看起来齐全，这种路径仍违反“项目脚本不能获得正式 release authority”的 Skill 边界。

8. **最终交付阶段没有闭合**
   - 项目本地创建 final completeness、authority、RDS writer、HTML report 和 final audit 脚本。
   - 12 个早期 unmodeled review 在 final completeness 中丢失绑定，导致交付任务再次停止。
   - 9.6 GB RDS 最初使用单线程 gzip；申请 64 CPU 却没有被利用，之后杀掉任务并改为 `pigz` 重投。

9. **事故登记不完整**
   - 项目 registry 只登记了 5 个早期问题，没有登记后续共享 Skill 热修改、contract adapter、手工 authority、final completeness 重试和 RDS writer 重启。

10. **形式完成不等于生物学质量已经可信**
    - 最终 Smooth muscle 为 89,156/296,188，约 30.1%；Theca 为 5,193，Endothelial 和 Pericyte/mural 各约 600。
    - 这些数量不能仅凭流程 PASS 判为错误，但结合既往 Smooth muscle–Stromal–Theca–mural 边界问题，必须在正式用户审阅中检查空间分布和多基因身份。
    - 该结果在固定版控制器重放前只能视为 `noncanonical_pending_review`，不得进入 Atlas 或训练参考。

### 2.2 D05521C3 连续停止暴露的问题

   - `run_lineage_controller.py`、`audit_post_merge_completeness.py`、`build_annotation_contract_v2.py` 和 ROI repair writer 均不同。
   - 控制器差异已经达到约 950 行，说明当前状态不是可接受的小型 hotfix，而是尚未整理、测试和提交的运行分支。

### 2.4 二级 mixed-subcluster 触发漏洞与已实施修复

旧控制器把 `local_split_worthy_group_program` 的“候选可见/可进入可分离性检查”错误提升为整个亚簇的 `mixed` 结论。共享类固醇生成、ECM、收缩背景和局部平滑信号因此可让一个已有清晰主身份的亚簇仍进入 P41；D05521C3 的冻结旧证据中，47/47 个二级亚簇、225,986/225,986 个 observations 均被路由到局部拆分，证明这不是合理生物学结果。

已实施的确定性修复为：

1. `candidate detected`、`local_split_worthy`、`independent identity` 和 `mixed` 成为四个不同状态。
2. 清晰 specific parent 仅在另一 candidate 同时具有独立亚簇级多基因、DEG/pseudobulk、相邻分辨率证据，并且双方具有达到最小规模的 pairwise-exclusive direct identity component 时才重开。
3. generic Stromal 不作为 specific lineage 的竞争者；但一个直接、完整的 specific component 和一个实质性 complement 可在 generic parent 内触发有界拆分。
4. 共享、嵌套或上下文 lineage-of-origin 程序记为 watch；两个独立但完全共表达、无法形成互斥组件的程序保留 `unresolved_biological`。
5. 局部拆分先使用已经计算的相邻 Leiden expression subcluster；只有仍未解析者才进入 candidate-local 空间 observation component。
6. 修复不改变全局 scoring 权重、subset 70/30/5% 验证门或 taxonomy。

对 D05521C3 的既有冻结评分进行只读重放后，仅 6/47 个二级亚簇、17,860/225,986（7.9%）observations 保留局部拆分；最大 cohort 从 21/21 全拆分降为 2 个真实可分离亚簇，18 个清晰 Luteal 亚簇直接返回，1 个不可分 Luteal–Immune 亚簇保留 unresolved。此次重放未修改样本 membership，也不把旧结果作为 fixture truth。

## 三、修复原则

1. 不修改当前 taxonomy、marker family、scoring 权重或发布阈值，除非独立生物学 fixture 证明必要。
2. 不重新设计 annotation engine；保留“第一轮 cohort 划分、第二轮主体注释、局部混合拆分、Atlas、羊卵巢复核、逐大类复核、最终发布”的主线。
3. 将脆弱判断下沉到确定性脚本、schema 和共享库；`SKILL.md` 只保留阶段不变量和操作入口。
4. 正式项目运行中禁止修改已安装 Skill。代码修复只能在仓库中完成、测试、安装为新版本，再由新 contract 继续。
5. 项目本地脚本可以做只读诊断或 experimental proposal，不能生成 stage authority、formal membership、release manifest 或 final RDS。
6. 每个受控暂停必须可恢复，且不需要重跑已经通过的 SCT/PCA/SNN/Leiden、Atlas mapping 或 ROI scoring。
7. 羊卵巢 Atlas 固定为当前已经使用的 GSE233801 参考，不在单样本项目中搜索、替换或临时重建其他 Atlas。
8. 最终逐大类复核必须是 Agent 主导的串行专项复核；禁止一次投递七八个 broad、统一计算后再做整体判定。
9. 共享 raw-count、坐标和 pseudobulk 基础缓存可以只计算一次，但一个缓存不能替代对一个具体细胞类型的独立生物学判断。

## 四、目标执行架构

### 4.1 标准 bootstrap

为 `init_annotation_project.py` 增加一个正式的 SCT+BANKSY RDS bootstrap 路径，统一完成：

1. 输入 RDS、raw-count assay、analysis set、初始排除项、坐标和 BANKSY grid 检查。
2. 支持常见 Seurat/BANKSY cluster 列名，并输出唯一标准 schema。
3. gzip 输入不依赖可选 `R.utils`；使用确定性 base-R/gzcon 或受检验的系统流。
4. 生成 input ancestry、runtime manifest、resource plan 和唯一初始 annotation contract。
5. 所有正式参数使用绝对路径；禁止 Agent 为每个项目重新写 audit R 脚本。

### 4.2 单一 contract 依赖注册表

建立一个代码级 `CANONICAL_RUNTIME_DEPENDENCIES` 单一来源，由以下三者共同导入：

- contract builder；
- contract validator；
- controller phase preflight。

测试必须证明三者集合完全相同。新增脚本若没有进入这个注册表，控制器测试直接失败，避免再次发生 `audit_local_split_workload.py` 漏绑定。

### 4.3 通用 membership transform ledger

新增共享 transform schema 和 validator，不再在 completeness 中为每种修复写独立例外。每个变换统一记录：

- `operation_type`；
- source/result membership 的物理与语义 hash；
- exact cell-ID delta；
- identity 字段是否改变；
- label 字段是否改变；
- assignment/depublication/unresolved 的 typed outcome；
- writer、stage authority、evidence 和 decision 的绑定；
- observation universe、互斥性和覆盖性。

最少支持：

1. Atlas unlabeled rescue；
2. post-merge unresolved component return；
3. follicle ROI exact assignment；
4. follicle ROI exact depublication；
5. identity-neutral source-unit synchronization；
6. per-broad exact cell-ID patch；
7. final unresolved -> typed QC materialization。

completeness 只沿有序 ledger 追踪来源，不再要求最终文件与某个早期文件物理相等，也不再依赖各脚本自定义的 provenance 字符串。

### 4.4 标准 resume 与状态机

在唯一控制器中实现正式 resume，而不是每个项目复制 contract 和写 adapter：

- `PASS`：阶段成功并可自动进入下一阶段；
- `REVIEW_REQUIRED`：证据/队列已成功生成，等待决定；
- `ITERATION_REQUIRED`：有明确、有限的生物学修订任务；
- `FAILED_RUNTIME`：软件、输入、资源或 provenance 真正失败；
- `DONE_PENDING_USER_REVIEW`：正式候选交付完成。

validator 可以内部使用 code 2 表示 open gate，但 controller 必须捕获并物化 `next_action_manifest.json`，正式 HNAICC wrapper 应正常退出，不让 scheduler 把受控暂停显示成软件失败。

resume token 必须绑定 contract、输入、当前 membership semantic hash、queue、decision 和已完成阶段。网络断线或会话压缩不影响项目状态。

### 4.5 串行逐细胞类型专项复核

这一阶段不是“catalog 批量审计”，而是对用户真实提问方式的标准化模拟。前面的 whole-tissue、第二轮 cohort、局部拆分、broad freeze、Atlas 和羊卵巢三项复核全部完成后，Agent 才开始本阶段。

#### 4.5.1 串行状态约束

1. controller 从当前已经发布的 broad、证据支持但暂时缺失的 broad，以及 Oocyte canonical 专项生成有序队列。
2. 同一时刻只能有一个 `active_cell_type_review`。其他类型保持 `queued`，不能并行生成正式结论或关闭状态。
3. Agent 必须先在对话中明确输出：`现在开始对 <cell type> 进行专项复核。`
4. 当前类型完成、必要修订已经写回、复算结果通过且 closure 冻结后，Agent 才能宣布进入下一个细胞类型。
5. 禁止一次性投递所有 broad 的复核任务，也禁止先计算七八类结果、最后用一段整体描述代替逐类判断。
6. 这里的“专项 Agent”表示一个独立的、串行的目标细胞类型审查会话；默认由当前主 Agent 逐项执行，不要求并行子 Agent。

#### 4.5.2 每个细胞类型必须主动提出的问题

Agent 不能只验证现有标签是否“看起来合理”，而要像用户提出问题时一样主动建立双向假设：

1. **是否过召回**：当前成员中是否混入最主要的竞争谱系、低信息背景或 ambient/邻接信号？
2. **是否欠召回**：在全 analysis set 的非当前成员中，是否存在被其他 broad 或 unresolved 吞掉的完整目标程序？
3. **身份边界是否合理**：该类型与最容易混淆的谱系应如何用文献、完整多基因程序、DEG/pseudobulk 和 anti-program 区分？
4. **空间结构是否合理**：空间分布是否符合组织学，但空间位置只能触发问题和验证结论，不能直接写标签？

例如：

- Granulosa：主动询问“是否欠召回、是否有弥散低置信 Granulosa、卵泡内层是否被 Stromal 或 Smooth muscle 吞掉”。
- Luteal：主动询问“当前大类是否混入大量 Theca/Stromal/low-confidence，独立黄体身份与真实 steroidogenic core 是否同时成立”。
- Theca：主动询问“是否被空间距离规则压低召回，完整 steroidogenic/androgenic 程序是否在全组织其他区域仍存在”。
- Oocyte：主动询问“是否存在 canonical object/cluster 漏召回”，不能凭数量先验或弱 zona 信号决定。

#### 4.5.3 一次专项复核的固定执行链

每个细胞类型严格执行：

1. **宣布目标与主要疑点**：给出当前数量、主要竞争谱系和需要排查的过召回/欠召回问题。
2. **读取目标类型参考**：读取 Skill 内针对该类型及竞争谱系的文献边界；必要时补充权威文献，但论文 marker 只构成假设，不直接分类。
3. **当前成员精度复核**：检查全部当前成员，不只抽样或只看原 source cohort。
4. **全样本欠召回复核**：扫描全部非当前成员和 unresolved，不把搜索范围限制在 Atlas conflict 或原父簇。
5. **分子身份复核**：联合项目自身 raw counts、多基因 family、target-vs-competitor DEG、全转录组 pseudobulk、direct/local 支持、anti-program 和替代解释。
6. **空间复核**：查看全组织高对比空间图、当前成员、欠召回候选和过召回问题成员，并与 Oocyte/follicle ROI/黄体/血管等相关结构交叉验证。
7. **专项判定**：输出 `保留 | 精确扩增 | 精确撤回 | 局部混合拆分 | 现有分区不可评估 | 证据不足保留 broad/unresolved`，不得整簇扩张或仅凭空间位置写回。
8. **必要修订与复算**：按 exact cell ID 应用修订；只在现有 source unit 真正不可评估时重算相关 cohort，不重跑整个样本。
9. **关闭当前类型**：简短报告支持依据、修改前后数量、主要空间结构、仍保留的不确定性，然后进入下一个类型。

#### 4.5.4 修订后的依赖处理

- 如果当前类型从另一个已关闭类型撤回或吸收成员，受影响的旧类型自动重新打开，但仍按一个类型一次的方式复核。
- 未受影响类型不重复计算完整重聚类。
- 所有类型关闭后再做一次全组织交叉一致性检查；该检查只能发现需要重新打开的具体类型，不能替代前述逐个专项复核。
- 每个类型最多两轮自动专项修订；仍有争议时保留 typed unresolved 并明确交给用户审阅。

#### 4.5.5 计算复用边界

为避免重复读取大型 RDS，可预先冻结一次全样本 raw-count marker matrix、library size、坐标和基础 pseudobulk cache。但是：

- 每次只为当前 active cell type 生成 target-vs-competitor comparison、空间候选和 decision packet；
- 不能用一次全目录批处理输出同时关闭多个类型；
- 共享缓存只有计算复用权，没有生物学 decision 或 release authority。

### 4.6 固定 GSE233801 Atlas

1. 唯一正式 Atlas 固定为当前使用的 GSE233801 羊卵巢参考。新项目使用从原始独立审阅 cluster 重建的只读、版本化 `sheep_ovary_GSE233801_split_wall_v2`；旧合并 v1 只用于已冻结任务断点续跑。
2. 实施时从当前成功使用的 reference 资产冻结原始来源、reference cell membership、标签 crosswalk、gene map、query-independent QC、固定特征、低维表示、ANN index、校准策略和全部 SHA。
3. 单样本项目只能引用该 bundle，禁止重新下载后临时重建、重新挑选“高置信标签”、替换其他 Atlas 或修改 crosswalk。
4. bundle 为每个 broad 固定 `supported | challenge_only | not_evaluable | unsupported` capability。`supported` 仍需当前 query 类别级校准才能救回未标注 broad；`challenge_only` 只能触发专项复核；缺乏可靠覆盖的谱系不能被它挑战、覆盖、救回或判定为缺失。
5. Atlas 仅在 broad freeze 后运行一次：对原本未标注、达到既定置信度、非 OOD 且 profile compatible 的 observation 按现有规则救回；与已有 broad 冲突者只能进入当前 query 的专项复核，不能静默覆盖。
6. Atlas 不产生 fine label，也不能取代后续逐细胞类型专项复核。
7. bundle 缺失或 SHA 不一致时状态为 `ATLAS_UNAVAILABLE` 并停止该阶段；禁止 Agent 自动寻找替代 Atlas。

### 4.7 标准 final release

`materialize_final_release` 必须一次性管理并可分步恢复：

1. final completeness；
2. unmodeled review 绑定；
3. final broad/fine/state/QC membership；
4. `final_cell_type` 写回；
5. RDS 原子写入和逐 cell-ID audit；
6. pending-user-review HTML 和图表；
7. release manifest。

大 RDS 使用控制器内置的并行压缩策略和临时文件原子 rename；报告先基于冻结 membership 生成，RDS 压缩失败时只重启 writer，不重跑 completeness 或生物学复核。

## 六、必须新增的回归测试

### 6.1 Bootstrap/runtime

- gzip scope 在没有 R.utils 时仍可读取。
- 上游 pre-QC universe 与 RDS analysis set 不同但边界明确时正确冻结。
- BANKSY 常见列名能标准化；缺 cluster/resolution 时明确失败。
- `stage`/`phase` 别名在输入边界统一，运行时只保留一种 canonical 名称。
- contract builder、validator、controller 的依赖集合完全一致。
- exact Python/R 环境缺 scipy、numpy、必需 R 包或脚本语法不兼容时在投递前失败。

### 6.2 Transform chain

- 单次正向 ROI assignment。
- 单次 exact depublication 到 unresolved。
- 两次 ROI repair 加一次 identity-neutral source sync。
- 链条包含 Atlas rescue、ROI assignment/depublication、per-broad patch 后仍能追溯每个最终成员。
- 相同 membership 的不同 gzip 文件语义相等；真正 cell-ID/label 差异必须失败。
- changes ledger 与 membership provenance 名称不一致必须在 apply 后立刻失败，而不是到 completeness 才发现。

### 6.3 状态机/resume

- 非空 Atlas queue 生成 `REVIEW_REQUIRED` 且调度任务成功结束。
- completeness 的正常 pre-review `BLOCKED` 被识别为下一步启动第一个细胞类型专项复核，而不是 runtime failure。
- 网络中断后从 current-stage manifest 恢复，不重复计算完成阶段。
- 已完成两次 repair 的项目从 chain checkpoint 恢复，不重跑 ROI clustering。
- typed directory artifact 与 file artifact 分开验证。

### 6.4 串行逐细胞类型专项复核

- 同一时刻只能存在一个 active cell type；同时激活两个类型必须失败。
- Agent/控制器未记录“开始当前类型专项复核”时不能生成该类型 closure。
- 每个 broad 恰好一个独立的目标类型 evidence packet，且必须覆盖当前成员精度、全样本召回、分子身份和空间合理性。
- 不能用一个 catalog-wide 批量 packet 或一次整体判定关闭多个类型。
- 每个类型都必须显式生成 over-recall 与 under-recall 双向假设，即使最终结论为没有发现问题。
- 项目本地脚本不能生成可接受的 stage authority。
- 只写自由文本或关键词不能关闭 challenger。
- patch 后受影响的已关闭类型必须重新打开；未受影响类型不能被无理由批量重算。
- 当前类型的零变更 closure 必须来自当前 membership 上的独立专项复核。
- Oocyte canonical、follicle ROI 与相关 broad packet 正确交叉绑定。

### 6.5 Atlas/final release

- 新 contract 只能接受固定 `sheep_ovary_GSE233801_split_wall_v2` bundle 及其完整 SHA；旧 v1 仅在绑定既有冻结 review state 的 resume 路径接受，替代 Atlas 必须失败。
- split-wall v2 的 Granulosa、Immune、Stromal/mesenchymal、Endothelial、Pericyte/mural 和 Smooth muscle 必须为独立 `supported` 原型；Epithelial/mesothelial 与 Theca 必须保持 `challenge_only`，Oocyte 与 Luteal 不得由该 Atlas 判定。
- 单样本项目重新物化 reference label、改 crosswalk 或重建 ANN index 必须失败。
- unmodeled review 从前序阶段一直绑定到 final completeness。
- 9–10 GB 级模拟 RDS 的 writer 使用并行压缩、临时文件和可恢复 checkpoint。
- final RDS 的 `final_cell_type` 与 frozen membership 对全部 cell ID 完全一致。
- final report 只使用一列 `final_cell_type`，不出现 `Vascular-associated`。

## 八、验收标准

1. 一个新的 SCT+BANKSY 样本只需输入路径和背景信息即可启动，不需 Agent 编写项目脚本。

3. 运行期间修改安装目录会被立即拒绝。
4. controller 能表示并验证两次 repair、exact depublication、source sync 和 per-broad patch 的任意合法顺序。
5. 所有 `REVIEW_REQUIRED`/`ITERATION_REQUIRED` 都有清晰 next action，且不会在调度器上伪装成软件崩溃。

7. final membership、RDS、HTML 和 audit 全部由 canonical final phase 生成并可断点恢复。
8. clean install 全测试通过，repo 与安装目录 SHA 一致。
9. C3 和 C05487C6 均可从已有稳定 checkpoint 收尾，无需重跑 whole-tissue 或全部二级 cohort。
