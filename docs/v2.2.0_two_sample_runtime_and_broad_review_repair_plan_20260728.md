# annotate-spatial-transcriptomics v2.2.0 双样本运行故障与逐大类复核修复计划

> 日期：2026-07-28
> 状态：用户已批准，修复实施中。
> 约束：当前先完成代码、schema 和回归测试；未重放样本、未推送 GitHub。
> 涉及样本：D05521A1、D05521C3。
> 本计划补充而不替代 `v2.2.0_algorithm_stabilization_plan_v2.md`；算法主线仍为“第一轮仅划分 cohort，第二轮重聚类承担主要注释，Atlas 后逐大类全样本复核”。

## 一、结论摘要

两个样本暴露的并不是一个单独阈值问题，而是三类可复现的系统缺陷：

1. **运行环境与资源未被完整预检**：Python 版本、依赖包、输入文件语义、相对路径和并行内存没有在提交前冻结，造成多次可避免的失败与重投。
2. **产物身份和证据链不稳定**：物理文件哈希被误当成生物学 membership 身份；目录修订后，已验证的来源证据没有沿变换链传递；事故登记与其 validation 也可失去同步。
3. **“逐大类复核”存在形式通过漏洞**：队列虽然为每个 broad 建了任务，但执行端可只复核少数类型，其余由项目脚本直接填写“supported/complete/consistent”；现有 validator 主要检查字段、关键词和值域，不能证明四项复核真的运行。因此，日志中的“目录复核 PASS”不等于每个细胞类型完成了当前成员精度、全样本召回、分子身份和空间合理性审查。

最高优先级是关闭第 3 类漏洞。否则运行层修好以后，流程仍可能产生“可通过校验、但没有完成生物学复核”的结果。

### 3.2 生物学与复核问题

1. Atlas 后形成了 9 个 broad 复核任务，但执行日志把它们缩减为“真正需要原始计数复核的只有 Oocyte 和两个 Immune 来源组”。其余类型没有形成可追溯的四项证据包。

3. 61 个 follicle ROI 中，F001、F002、F005 存在 Theca interna/vascular interna 欠召回或未解析，必须做有限 ROI 的原始计数复核；空间几何只能触发复核，不能直接决定标签。
4. 逐大类队列中的所有任务都应覆盖完整 analysis set，而不是只有被选中的少数 source group 才称为“完成复核”。source group 只能是某个 broad 任务内部的证据分层。

### 4.3 逐大类复核的关键流程漏洞

C3 的 round-1 队列确实包含 8 个 broad 任务，但项目本地脚本直接硬编码了结论：Epithelial/mesothelial 删除 52 个、Immune 删除 34 个，其余类型统一填写 `supported / complete / consistent / supported`。该脚本没有读取原始 counts、DEG/pseudobulk、成对竞争或实际空间证据。

当前 validator 的主要校验方式是：

- 字段值是否属于允许集合；
- `evidence_basis` 文本中是否出现 `query`、`marker/DEG/pseudobulk`、`spatial` 等关键词；
- patch 文件是否存在且 hash 匹配。

因此，项目脚本只要写出合规词语，就能得到结构性 PASS。round 2 队列为空也只是“前一轮决策被登记为关闭”，不是重新计算后确认全部 broad 已关闭。这是本计划的 P0 缺陷。

## 六、目标复核架构

流程名称固定，不允许 Agent 用近义词替代或省略阶段：

1. `Atlas 后暂定注释`
2. `未解析成员局部复核`
3. `最终完整性初审`
4. `羊卵巢三项复核`
5. `逐大类全样本复核`
6. `精确成员修订`
7. `修订后重新复核全部大类`
8. `最终完整性与羊卵巢三项复核`
9. `pending_user_review 报告`

其中“逐大类全样本复核”必须把每个已经注释出的 broad 当作一个完整任务。常见/候选但零普查的 broad 则建立 `missing_broad_review`。每个任务必须同时得出四项结论：

### 6.1 当前成员精度

- 审查该 broad 的全部当前成员，而不是抽取几个 source group 后代表全体。
- 分析多基因身份支持、低 RNA 继承、竞争谱系、anti-program、source subcluster 和空间组件。
- source group 只用于解释内部异质性，不能成为跳过 whole-broad 审查的理由。
- 结论：`supported | over_recall_detected | not_evaluable`。

### 6.2 全样本召回

- 在所有非该 broad 的 observation 中扫描该谱系，不限于原 cohort、Atlas conflict 或已有 watch。
- marker-family 候选只能提出待审查组件；正式召回还需 full-transcriptome DEG/pseudobulk、竞争谱系和空间连贯性。
- generic Stromal/mesenchymal 不允许使用 marker-only 在全样本扩张；其欠召回主要来自 specific-lineage 修订后的 exact remainder 或有独立基质程序的群体证据。
- Oocyte 必须进入 canonical query-only targeted workflow，不能使用普通 marker component 直接召回。
- 结论：`complete | under_recall_detected | confirmed_absent | not_evaluable`。

### 6.3 分子身份

- 必须绑定项目自身非 SCT raw-count assay。
- 联合多基因 family、当前类型与外部候选的 DEG、全转录组 pseudobulk、成对 discriminator、anti-program 和技术替代解释。
- 单一 marker、单一空间组件、共享 ECM/收缩/类固醇程序不能独立支持正式身份。
- 结论：`supported | mixed | unsupported | not_evaluable`。

### 6.4 空间合理性

- 同时显示当前成员、全样本召回候选、过召回 challenger 和组织背景。
- 判断是否形成合理的表面、卵泡、血管、黄体、基质或其他组织结构；空间位置只作联合证据，不作为 Theca/Luteal 等类型的硬入选门。
- 羊卵巢还必须与 Oocyte 和 follicle ROI 专项结果交叉核对。
- 结论：`consistent | localized_issue | inconsistent | not_evaluable`。

四项中任一项未计算或 `not_evaluable` 时，该 broad 不能被“看起来合理”而自动关闭。只有明确记录无法评估原因并经最终 unresolved 路径处理，才可结束项目。

## 七、证据产物与校验权限重构

### 7.1 每个 broad 的标准 evidence pack

每个 broad 必须生成独立、hash-bound 的 evidence pack，至少包含：

- 当前成员完整 cell-ID semantic hash 和来源构成；
- raw-count marker-family 汇总及 observation 分布；
- 当前成员中竞争谱系/anti-program 问题清单；
- whole-query recall 候选组件及其精确 cell IDs；
- current、recall candidate、origin/competitor 的全转录组 pseudobulk；
- target-vs-outside、candidate-vs-origin 和关键 pairwise DEG/差异摘要；
- 全组织空间图、candidate/challenger 空间组件指标；
- Oocyte 或 follicle ROI 等专项交叉引用；
- 四项机器可读结论的计算指标与阈值版本。

当前新增的以下脚本方向可保留，但还不能单独构成完整复核：

| 组件 | 保留价值 | 必须补强的内容 |
|---|---|---|
| `build_cell_type_review_marker_manifest.py` | 从 profile/catalog 生成完整 broad marker manifest，并排除 subtype/state | 加入候选零普查覆盖审计和 profile/catalog schema 校验 |
| `export_cell_type_review_counts.R` | 从项目本地非 SCT raw counts 导出 marker 证据 | 绑定 input contract、assay ancestry semantic hash 和 exact runtime |
| `build_broad_cell_type_review_evidence.py` | 以 broad 为单位生成 precision/recall/spatial challenger，且不直接写标签 | 当前只遍历 present broad；需同时为 missing/watch broad 建任务；marker component 仅为候选，不能被误当结论 |
| `export_broad_cell_type_review_pseudobulk.R` | 一次稀疏矩阵乘法生成 current/recall pseudobulk，避免反复读取大对象 | 补足 competitor/anti/reference group 设计，确保每个 broad 有完整 comparison set |
| `summarize_broad_cell_type_review_pseudobulk.py` | 提供全转录组相似度和差异摘要 | 不能把 pseudobulk 相似度当分类器；需输出可验证的 DEG/competitor 证据索引 |
| `validate_catalog_wide_lineage_review_decisions.py` | 保留队列全覆盖、值域、patch hash 和 outcome 约束 | 删除关键词证明逻辑；改为读取并验证 evidence pack、四项计算结果、membership semantic hash 和交叉证据 |

### 7.2 权限分离

- **Evidence builder**：只能生成证据，不能写正式 membership。
- **Decision proposer**：可根据证据提出 retain/patch/targeted review，但不能自证 PASS。
- **Validator**：必须独立读取 evidence pack 并重算关键指标；不接受自由文本作为证据。
- **Membership applier**：只接受 validator 通过的 exact cell-ID patch；不接受行号、整簇默认扩张或项目脚本直接写正式标签。
- **Final completeness validator**：沿 membership transform ledger 追踪每个成员来源，并确认全部 broad 复核已关闭。

项目本地脚本可以生成 experimental proposal，但不能具有 release authority。C3 当前硬编码 decision 脚本及其 round-1/round-2 产物应登记为 `failed_diagnostic_review`，不得作为正式复核结果。

### 7.3 修订轮次

1. Round 1 为全部 broad 生成新 evidence pack 和四项结论。
2. 需要修订时，只按 exact cell IDs 应用 patch；若现有分区确实不可评估，才重算相关 source cohort，不重跑全部两轮聚类。
3. 任何 patch 后重新生成所有 broad 的 evidence pack。不能仅把上一轮已填“retain”的类型自动复制为关闭。
4. 最多两轮自动修订；仍未关闭时返回具体 broad/Oocyte/ROI 给用户审阅，不继续调全对象阈值。

## 八、运行层修复

### 8.1 Exact-runtime preflight

新建统一 preflight manifest，逐阶段检查：

- Python/R 可执行文件绝对路径及版本；
- 每个即将调用的 Python 脚本可由该解释器编译；
- numpy/scipy/sklearn 等实际 imports；
- R 包和版本；
- Atlas 模型构建与运行版本兼容性；
- 每个输入的语义类型、reader、schema 和 hash；
- 所有传递给 R/Python 的路径已经绝对化且存在。

任一项失败时禁止投递正式任务。

### 8.2 资源规划

- 大型 cohort 默认 `resolution_workers=1`、scoring worker 也使用保守设置。
- 64 CPU 用于 SCT/PCA/SNN/Leiden 内部线程、矩阵运算或并行独立 cohort，不在同一 Seurat 对象上 fork 多个 resolution worker。
- 资源估算至少包含：对象序列化大小、raw counts/SCT 中间体、邻接图、每 worker 复制倍数、R 内存峰值安全系数。
- 依据 A1/C3 的实测峰值建立分档；预测超过 allocation 的任务在提交前失败，而不是运行数十分钟后由 scheduler 杀死。
- 完成一个 cohort 后记录实际 MaxRSS，反馈更新估算参数，但不改变生物学阈值。

### 8.3 路径与输入语义

- 控制器入口立即执行 `resolve()`，后续 manifest 只写绝对路径。
- R entrypoint 不得通过 `chdir=TRUE` 改变输入路径语义；如必须 source 到脚本目录，先冻结所有输入绝对路径。
- context TSV、JSON manifest、membership TSV、RDS 等均以 schema/media type 分派 reader，禁止按扩展名或调用者猜测。

### 8.4 受控暂停

- `REVIEW_REQUIRED` 是合法的可恢复状态，不登记为软件失败。
- Atlas discrepancy、逐大类 targeted raw-count review 和用户审阅分别使用明确 pause reason。
- 恢复时必须绑定原 queue hash、decision hash 和冻结输入；queue 改变则创建新 round，不能静默复用旧 decision。

## 九、产物身份与证据链修复

### 9.1 双重哈希

所有 membership 保存：

- `physical_sha256`：审计具体文件字节；
- `semantic_membership_sha256`：对规范化、排序、去重后的 cell-ID 集合或 cell-ID→label 映射计算；
- observation count、duplicate count 和 exact set coverage。

cache 兼容性以 semantic hash、输入对象 hash、参数、seed 和代码 hash 联合判断。gzip 重写但语义相同不应使 cache 失效；语义不同则即使文件名相同也必须拒绝。

### 9.2 Membership transform ledger

每次 Atlas rescue、局部 split、catalog patch、ROI repair 或 final writeback 都记录：

- source membership artifact；
- delta membership 和操作类型；
- result membership artifact；
- source/delta/result semantic hash；
- 互斥性、覆盖性和允许标签；
- 上游 evidence/decision validator；
- 是否改变 broad/fine/state/QC。

post-catalog completeness 必须沿该链验证来源，不能只要求最终 membership 与某个早期文件直接相等。

### 9.3 Incident registry

- registry validation 绑定 registry 当前物理 hash、语义 hash、row count 和生成时间。
- registry 追加或修改后，旧 validation 自动判 stale。
- 最终发布要求所有 incident 为 `closed/closed_repaired`，或存在用户批准的 typed waiver；`open_pending_repair` 不能被报告 PASS 掩盖。

## 十、羊卵巢专项闭环

逐大类复核不能替代三项羊卵巢复核，三项复核也不能替代逐大类全样本复核。两者必须交叉验证：

1. **所有 broad 的全组织空间合理性**：检查表面、卵泡、血管、黄体、基质等区域，不以空间位置单独定标签。
2. **Oocyte 可信度**：完整 canonical targeted cohort、空间对象、污染解释和邻近颗粒细胞边界；canonical 绑定为空不得关闭。
3. **Follicle ROI 层次**：颗粒层、Theca/血管层、非血管平滑肌样层、外侧基质的整体组织学层次；只重算失败 ROI。

D05521A1 重放时必须明确关闭 Oocyte canonical 问题及 F001/F002/F005，而不是仅凭逐大类队列 PASS 生成最终报告。

## 十二、测试计划

### 12.1 运行与资源测试

### 12.2 Evidence-bound 逐大类复核测试

- 每个 present broad 恰好一个 full-query review task；source group 不能替代 broad task。
- missing/watch broad 也必须有 `missing_broad_review`。
- 缺少任一 raw-count、DEG/pseudobulk、competitor 或 spatial artifact 时不能 retain broad。
- 仅在 `evidence_basis` 写入关键词必须失败。
- 伪造的四项 categorical PASS 与真实指标冲突时必须失败。
- 项目本地 decision script 不能自授 release authority。
- patch 后不重新生成所有 broad evidence pack 时 round 不能关闭。
- round 2 为空只能由“当前 membership 上重新计算后全部关闭”产生，不能继承 round 1 的文本 decision。
- Oocyte 没有 canonical workflow artifact 时不能关闭。
- Generic Stromal 不能通过 marker-only whole-query recall 扩张。

### 12.3 产物身份与证据链测试

- 两个 gzip 文件字节不同但 cell-ID 集合相同：physical hash 不同、semantic hash 相同，允许 partition cache 复用。
- cell-ID 集合改变一项：semantic hash 必须不同并拒绝 cache。
- component rescue → catalog patch → completeness 的链可追溯并通过。
- 任一 transform 中断、delta 重叠或 result 不覆盖时必须失败。
- incident registry 增加一行后旧 validation 必须立即失效。
- Skill 脚本修改后旧 contract 必须继续被拒绝，验证现有 hash guard 不被削弱。
